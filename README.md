# track-splice 轨迹拼接工具

以 2 条或多条现有轨迹为路网，按顺序点选锚点，自动拼出一条新轨迹。
**硬约束：新轨迹的每个点都取自原有轨迹的原始坐标，不发明任何新路段。**

在线版（GitHub Pages，浏览器直接打开即用）：
<https://jason-xhy.github.io/outdoor/track-splice.html>

## 设计（2026-10-13，用户确认）

- 形态：单文件 HTML 地图工具（Leaflet 1.9.4 内嵌，离线可用；底图默认 ArcGIS
  World Imagery 卫星图——WGS84 无偏移，可切 OSM）
- 输入：多个 2bulu KML（`gx:Track`）、标准 LineString KML、GPX
- 建图：每条轨迹内部相邻点连无向边（边权 = 3D 距离）；**跨轨迹**容差内
  （默认 10m，可调 5–30m）的点合并为同一节点；**同轨内不合并**（防止把
  之字形山路抄近）；同轨连续重复点去重
- 选路：相邻锚点间 Dijkstra 总路程最短；不可达则报错指明哪一段，绝不拉直线
- 锚点吸附：按轨迹各取最近点组成候选集（≤100m 内纳入，全部超限回退最近
  单点），路由在候选间择短——两轨端点重叠区（同一登山口两次记录，GPS 偏差
  几十米）不会因单侧吸附绑死到不连通的一侧而绕大圈；导出锚点坐标取路线
  实际经过的节点（2026-10-13 实锤修复：7→8 段 14.36km 绕行 → 3.49km 直达）
- "原路返回"无需专门功能：路网无向，去程边回程自然可走
- 统计：总里程、累计爬升/下降（5 点滑动平均去 GPS 噪声）、分段距离
- 输出：KML（2bulu 可导入，3D 坐标）+ GPX 1.1 双导出，锚点导出为命名路点

## 目录

- `src/track-core.js` 纯逻辑（解析/建图/路由/统计/导出），UMD：浏览器挂
  `window.TrackCore`，Node 下 `module.exports`（可测试）
- `src/app.js` UI 交互（Leaflet、锚点管理、面板）
- `src/shell.html` 页面模板（含 `<!--INLINE:xxx-->` 占位符）
- `build.py` 把 leaflet.css/js + track-core.js + app.js 内联进模板，产出
  单文件 `track-splice.html`
- `test/test-core.mjs` Node 测试（真实轨迹用例 + 硬约束断言）
- `test/data/` 两条武功山真实轨迹——**个人隐私数据，.gitignore 排除不入库**；
  克隆后本地自备同名文件方可跑通引用真实轨迹的用例（合成数据用例可直接跑）

## 用法

浏览器打开 `track-splice.html` → 拖入/选择 KML/GPX 文件 → 依出行顺序在地图
上点击添加锚点（自动吸附最近轨迹点，可命名/排序/删除）→「计算路线」→
预览与统计 →「导出 KML / 导出 GPX」。

## 首个验收用例

图平坳 → 香炉峰 → 鸡婆岩 → 原路返回 → 徐霞客步道 → 武功山金顶 → 下撤
（终点 1015m 一侧）。两条源轨迹在 ~1210m 海拔处共享路段（最近 5.1m，
30m 内 53 点对），路网连通，整条行程可拼。
